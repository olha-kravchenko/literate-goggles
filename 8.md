# Розділ 8: Обґрунтування вибору типу бази даних

## Вступ
Для інформаційної системи обліку студентів важливо обрати відповідний тип бази даних, який забезпечить надійне зберігання, швидкий доступ та ефективну обробку даних. Після аналізу вимог системи та порівняння різних типів баз даних, було обрано реляційну базу даних.

## Аналіз варіантів
- **Реляційні бази даних (SQL)**: Підходять для структурованих даних з чіткими зв'язками, такими як студенти, дисципліни, оцінки.
- **Нереляційні бази даних (NoSQL)**: Кращі для неструктурованих даних або великих обсягів, але менш ефективні для складних запитів та транзакцій.
- **Графові бази даних**: Підходять для складних зв'язків, але надлишкові для цієї системи.

## Обґрунтування вибору
Обрано PostgreSQL як реляційну базу даних з наступних причин:
1. **ACID-властивості**: Забезпечують цілісність даних при одночасному доступі (наприклад, коли викладач і адмін редагують оцінки).
2. **Підтримка складних запитів**: SQL дозволяє легко формувати звіти, фільтрувати дані за групами, семестрами тощо.
3. **Зв'язки між сутностями**: Реляційна модель ідеально підходить для моделювання студентів, груп, дисциплін та оцінок.
4. **Безпека та надійність**: Вбудовані механізми аутентифікації, шифрування та резервного копіювання.
5. **Масштабованість**: Підтримує вертикальне та горизонтальне масштабування.
6. **Відкритий код**: Безкоштовний, з великою спільнотою та підтримкою.

## Висновок
Реляційна база даних забезпечує всі необхідні функції для системи обліку студентів, гарантуючи надійність, продуктивність та зручність використання.
